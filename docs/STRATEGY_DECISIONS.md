# 정해주셔야 할 것 / 제가 임의로 고친 것

`bucket-dca` 재설계를 진행하며 나온 것들입니다. 실험 결과 표는
[STRATEGY_LAB.md](STRATEGY_LAB.md)에, 용어 설명도 그 문서 앞부분에 있습니다.

## A. 제가 임의로 고친 것 (되돌릴 수 있음)

돌려보다 명백히 잘못된 것으로 판단해 손댄 부분입니다. 판단 근거를 같이 적어두니
동의 안 되시면 되돌리면 됩니다.

### A1. 주간 배포 상한을 자산 대비 비율로 — `max_deploy_per_week_pct = 0.05`

**증상.** 포트폴리오의 평균 33%, 마지막에는 61%가 투자되지 않은 현금이었습니다
(비교: `momentum-dca`는 0.8%). 그것만으로 연 11%p를 잃고 있었습니다.

**원인.** `max_deploy_per_week_usd = 700`은 **매수만 하던 전략** 시절의 값입니다.
당시엔 유입이 월 적립금($543)뿐이라 상한에 걸린 적이 한 번도 없었습니다. 그런데
교체 매도가 생기면서 포지션 하나를 정리한 $15,000이 계좌로 돌아오는데, 주당 $700씩
밖에 못 넣습니다. 다 넣는 데 21주가 걸리고 그사이 다음 매도가 들어옵니다.

**고친 방식.** 원래 의도("쌓인 돈을 한 주에 한두 종목에 몰아넣지 말자")는 살리되,
자산 대비 비율로 바꿔 계좌가 커지면 같이 커지게 했습니다. 고정 달러값은 계좌가
작을 때의 **하한**으로만 남겼습니다(둘 중 큰 값 사용).

> **확인 필요:** 5%가 적정값인지는 LAB 1번 표를 보고 정하시면 됩니다.

### A2. 교체 매도를 리밸런스 세션에만 — 매일 → 주 1회

점수는 63/126/252일 lookback으로 만든 몇 달짜리 신호인데 매일 판정하고 있었습니다.
**성과는 바뀌지 않았습니다**(`exit_cooldown_days=3`이 이미 반복을 막고 있었음).
다만 리밸런스일에만 42종목을 채점하므로 백테스트가 5배 빨라졌습니다. 제가 처음에
"버그에 가깝다"고 한 건 과했고, 실제로는 성능 개선입니다.

### A3. 매도 사유를 순위 → 절대 조건으로 — `require_absolute_exit = True`

순위 기반은 **남이 좋아져서** 팔립니다. 강세장에선 9위 종목도 절대 수익률이 훌륭할
수 있고, 60% 올라 있지만 2위에서 9위로 식은 종목을 무너진 종목과 똑같이 잘라냅니다.
바꾼 뒤 매도 483 → 223건, TWR 11.13% → 15.81%.

`require_absolute_exit=False`로 예전 규칙을 그대로 되살릴 수 있게 남겨뒀습니다.

### A4. 백테스트 측정 오류 4건 (커밋 `668272a`)

- **워밍업** — 전략이 첫 1.03년을 현금으로 앉아 있는 동안 기준선은 투자 중이었음.
  "어느 해를 비켜갔나"를 재고 있었지 전략을 재고 있지 않았음.
- **환율** — 2012~2026 전 구간 상수 1350원. 실제로는 1150 → 1380.
- **후발 상장 종목** — 창이 열린 뒤 상장한 종목을 통째로 버림. IONQ가 매번 사라졌음.
- **휴장일 종료** — `end`가 토요일이면 전 종목을 버리고 "캐시에 없음"이라 보고.

### A5. 유니버스에 버킷 개념과 안전자산 추가

`Instrument.bucket`(`SAFE`/`CORE`/`GROWTH`) 신설. `SHY`(미국 1-3년 국채)와
`GLD`(금)를 SAFE로, `IONQ`를 GROWTH로 옮겼습니다. 둘 다 2005년 이전부터 일봉이
있어 백테스트 가능 구간이 짧아지지 않습니다.

### A6. 양도소득세를 백테스트 비용에 추가 — `src/backtest/tax.py`

안 팔던 전략에서는 실현이익이 없어 빼도 됐지만, 회전하는 전략에서는 **매도 규칙을
바꾸는 모든 설정이 이 비용을 바꿉니다.** 세금 0으로 비교하면 계좌가 실제로는 낼 수
밖에 없는 비용을 없는 셈 치고 순위를 매기게 됩니다.

연간 손익 합산 → 기본공제 차감 → 정률 과세, 손실 이월 없음, 이듬해 초 현금 차감.

> **확인 필요:** 세율 22%·공제 250만원을 상수로 넣어뒀습니다. 바뀔 수 있는 값이니
> 실제 적용 전 현재 기준을 확인해 주세요. `src/backtest/tax.py` 한 곳만 고치면 됩니다.

### A7. 비교 기준선에 "같은 배분" 곡선 추가

안전자산 20%를 든 전략을 100% 주식 곡선에 대는 건 구조적으로 지는 비교입니다.
같은 20/80 배분의 무전략 곡선을 기준선에 넣었습니다. 이게 진짜 비교 대상입니다.

| | |
|---|---|

| **평가 기준** | **낙폭당 수익.** 수익 30 / 낙폭 20이 수익 40 / 낙폭 40보다 낫습니다 |
| **종목 수** | **자유** — 10종목은 임의로 정한 값이었고 지킬 필요 없음 |
| **A절 임의 수정 전부** | 승인됨 |

> **기준을 한 번 잘못 읽었습니다.** −40%를 "채워야 할 예산"으로 해석해서 낙폭이
> 얕은 설정을 "예산을 절반만 쓴다"며 탈락시켰습니다. 실제 기준은 **"10%p 더 벌자고
> 낙폭을 20%p 내주지는 않는다"**이고, 그러면 순위가 정반대가 됩니다.

### 이 기준으로 다시 매긴 순위

평균 수익 ÷ 최악 구간 낙폭:

| 설정 | 평균 수익 | 최악 MDD | 수익/MDD |
|---|---|---|---|
| **A 보수 (방어 조합 셋)** | **26.18%** | **21.19%** | **1.24** |
| 변동성조정 끔 + 추세이탈 매도 | 28.94% | 25.87% | 1.12 |
| 현재 기본값 | 24.38% | 22.71% | 1.07 |
| momentum-dca | 38.10% | 42.78% | 0.89 |
| B 균형 (무매도 + 안전 30) | 25.54% | 30.61% | 0.83 |
| 기준선 (무전략) | 25.99% | 32.04% | 0.81 |
| 무매도 + 변동성조정 끔 | 33.17% | 43.13% | 0.77 |
| C 공격 | 31.26% | 41.55% | 0.75 |

**A안이 1위입니다.** 그리고 **기준선보다 평균 수익이 높으면서(26.18% vs 25.99%)
낙폭은 11%p 낮습니다.** 무전략을 수익·위험 양쪽에서 이기는 유일한 설정입니다.

`momentum-dca`가 평균 38.10%로 수익은 가장 높지만, 그걸 위해 낙폭 42.78%를
치릅니다 — 정확히 말씀하신 "10%p 더 벌자고 20%p 내주는" 거래입니다.

```
trend_sma = 150                      추세 필터 150일
나머지는 현재 기본값 (안전 20 / 일반 60 / 성장 20, CORE 6슬롯, 슬롯 점유)
```

|---|---|---|---|---|---|
| TWR | 23.32% | 23.48% | 25.21% | 31.68% | 27.21% |
| MDD | 19.81% | 17.87% | 18.03% | 18.44% | 21.19% |

**낙폭이 5구간 전부 22% 미만이고 범위가 17.9~21.2%로 이 실험에서 가장 좁습니다.**
어느 시점에 시작해도 낙폭이 비슷하다는 뜻입니다.

### 최종 설정 (코드 기본값에 반영 완료)

30개 그룹 · 495회 백테스트를 낙폭당 수익 기준으로 훑은 결과입니다.

```yaml
# src/strategy/bucket_dca.py 의 BucketDcaParams 기본값
bucket_weights:  SAFE 20 / CORE 60 / GROWTH 20    # 안전 20% — 확정하신 값
bucket_slots:    SAFE 2 / CORE 6 / GROWTH 2       # 9종목 (GROWTH는 IONQ 하나뿐)
prefer_incumbents: true                            # 보유 종목이 슬롯 유지
require_absolute_exit: true                        # 순위가 아니라 모멘텀 소멸로 매도
exit_requires_trend_break: true                    # ← 변경. 자기 추세 이탈까지 확인
unfilled_weight_to: SAFE                           # ← 변경. 못 채운 몫을 안전자산으로
trend_sma: 150                                     # ← 변경 (기존 200)
max_deploy_per_week_pct: 0.20                      # ← 변경 (기존 0.05)
vol_adjust: true                                   # 유지 — 끄면 낙폭이 두 배
```

| | 2014 | 2016 | 2018 | 2020 | 2022 | 평균 |
|---|---|---|---|---|---|---|
| TWR | 25.10% | 25.61% | 27.88% | 32.12% | 27.62% | **27.67%** |
| MDD | 21.30% | 19.31% | 18.43% | 18.52% | 20.61% | 최악 **21.30%** |
| 기준선 TWR | 28.31% | 27.10% | 26.39% | 25.88% | 22.27% | 25.99% |
| 기준선 MDD | 32.04% | 27.48% | 24.80% | 23.70% | 18.94% | 최악 32.04% |

**수익/낙폭 1.30.** 무전략 기준선(0.81)을 크게 앞서고, 평균 수익도 1.7%p 높으면서
최악 낙폭은 10.7%p 낮습니다. 낙폭이 5구간 전부 22% 미만이라 **−40% 상한까지는 절반
가까이 여유가 있습니다.**

### 이번 탐색에서 뒤집힌 것 두 가지

**1. 교체 매도는 있는 편이 낫습니다.** 앞서 "안 파는 게 연 5~8%p 낫다"고 했는데,
그건 **방어 장치가 없던 설정 기준**이었습니다. 추세 이탈 확인이 붙은 지금은 끄면
비율이 1.30 → 0.82로 떨어지고 낙폭이 21.30% → 31.65%로 뜁니다.

**2. 배포 상한 5%도 여전히 조이고 있었습니다.** 20%로 열면 5구간 전부 수익이 오르고
낙폭은 0.1%p만 오릅니다. 15/20/30/무제한이 소수점까지 같아 **곡선이 15% 근처에서
평평해집니다** — 20%는 그 평지의 안전한 지점입니다.

### 채택하지 않은 것

| | 이유 |
|---|---|
| 변동성 조정 끔 | 수익 +2.5%p / 낙폭 +7.3%p → 비율 0.99 |
| 교체 매도 끔 | 비율 0.82 |
| CORE 2슬롯(5종목) | 2014년 낙폭 **42.16%** — −40% 상한 초과 |
| CORE 8·10슬롯 | 낙폭은 조금 낮지만 수익이 더 깎임 (비율 1.21·1.22) |
| 부분 매도 · min_score · 리밸런스 요일 | 전부 비율 하락 |
| 못 채운 몫을 CORE로 | 수익 +0.5%p / 낙폭 +1.6%p → 비율 1.23 |

### 아직 안 바꾼 것

`config.yaml`의 활성 전략은 **여전히 `momentum-dca`입니다.** 실제로 `bucket-dca`로
전환할지는 결정하실 부분이라 건드리지 않았습니다. 바꾸시려면:

```yaml
trading:
  strategies:
    - src.strategy.bucket_dca:BucketDcaStrategy
```

## B. 제가 정할 수 없는 것 — 결정해 주세요

### B0-old. (기록) 모양 대 수익 — 제약 확정 전의 정리

실험이 끝났습니다. 상세 근거는 [STRATEGY_FINDINGS.md](STRATEGY_FINDINGS.md)의
"최종 권장 — 3안"에 있습니다. 요약만:

| | 종목 | 매도 | 세금 | 수익 | 낙폭 | 기준선 대비 |
|---|---|---|---|---|---|---|
| **A 보수** | 9 | 43건 | 437만 | 23~32% | **17.9~21.2%** | 수익 3패 / **낙폭 5승** |
| **B 균형** | 20 | **0** | **0** | 20~30% | 18.5~30.6% | 수익 4패 / 낙폭 5승 |
| **C 공격** | 18 | **0** | **0** | 24~36% | 22.5~41.6% | **수익 5승** / 낙폭 4패 |

- **A** — 원하셨던 모양(10종목·안전 20%)을 유일하게 지킵니다. 낙폭이 어느 시점에
  시작하든 22% 미만으로, 예측 가능성이 가장 높습니다.
- **B** — 종목 수 상한을 포기하는 대신 **매매를 완전히 없앱니다.** 세금 신고도
  매도 판단도 없어 운용 부담이 가장 적습니다.
- **C** — 수익으로 기준선을 이기는 유일한 안. 대신 **2014년에 41.55% 낙폭**을
  지나야 합니다(1억 → 5,845만원).

**판단 기준은 수익률이 아니라 "얼마나 깨지는 걸 버틸 수 있는가"입니다.** 못 버티고
파는 순간 어느 안의 수익률도 의미가 없어집니다.

세 안 모두 코드에 파라미터로 존재합니다. 고르시면 `config.yaml`의
`trading.strategy_params`에 적용하고, 기본값도 그에 맞춰 바꾸겠습니다.

### B0-1. (배경) 모양과 수익의 교환

실험 전체에서 가장 큰 결과입니다. **팔지 않는 쪽이 매년 5~8%p 이깁니다.**

| | 2014 | 2016 | 2018 | 2020 | 2022 | 매도 | 세금 | 보유 |
|---|---|---|---|---|---|---|---|---|
| 기준선 (무전략) | 28.31% | 27.10% | 26.39% | 25.88% | 22.27% | — | — | 42 |
| 교체 매도 켬 (현재) | 20.98% | 21.81% | 22.57% | 33.15% | 23.39% | 45 | 330만 | **9** |
| 교체 매도 끔 | **28.60%** | **29.59%** | **26.73%** | **35.07%** | 20.31% | **0** | **0원** | 19 |

매도 건수와 성과가 거의 완벽하게 역상관입니다(597건 → 90 → 45 → 0으로 갈수록 수익이
단조롭게 상승). 그리고 **0건이 유일하게 기준선을 이깁니다.**

대신 잃는 것: 동시보유 9 → 19종목(원하신 상한이 사라짐), 2014년 MDD 20.78% → 33.68%,
2022년 수익 23.39% → 20.31%.

**결정 필요.** 셋 중 하나입니다.

1. **모양을 지킨다** (현재) — 9종목, 낙폭 20~23%로 일관. 대신 수익이 기준선에 짐.
2. **수익을 지킨다** — 교체 매도를 끈다. 19종목, 낙폭 19~34%로 널뜀.
3. **중간** — 교체 매도는 끄되 슬롯 수를 줄여 종목이 덜 늘게 한다. 3차 실험에서
   확인 중.

**튜닝으로 해결되는 문제가 아닙니다.** 종목 수를 묶으려면 팔아야 하고, 파는 순간
비용이 붙습니다. 제가 정할 수 없는 교환이라 그대로 올립니다.

### B1. 🔴 토스 계좌가 비어 있습니다 (LIVE 이전에 유일하게 막는 것)

```
KRW cashBuyingPower: 0
USD cashBuyingPower: 0
holdings: 0건
```

`_budget()`은 USD 매수여력이 0이면 `ZERO`를 반환하고, 전략은 **신호를 하나도 내지
않습니다.** LIVE로 켜도 아무 일도 일어나지 않습니다.

더 나쁜 건 **그 침묵이 정상처럼 보인다**는 겁니다. dry-run이 이미 그랬습니다:

```
momentum-dca: 신호 0건
>>> 신호가 없습니다.
```

"게이트→발주 경로 정상"인지 "돈이 없어서 아무것도 안 함"인지 화면상 구분이 안 됩니다.
8일간 리포트가 안 돌던 사고, 리밸런스 요일이 휴장이라 그 주를 건너뛰던 버그와 **같은
종류의 침묵**입니다.

**결정 필요:** 입금하시고, 그 뒤 USD 매수여력을 확인해야 합니다. 원화만 넣었을 때
토스가 자동 환전을 해주지 않으면 USD 여력은 계속 0이고 전략은 영원히 침묵합니다.
`src/toss/` 어디에도 환전 API가 없습니다(`exchange_rate()`는 시세 조회일 뿐).

### B2. 🔴 실거래 리스크 한도를 다시 잡아야 합니다

`max_daily_notional_krw: 5,000,000`은 주당 $500만 사던 전략 기준입니다. 회전하는
전략에서는 첫 백테스트에서 **매도 4,460건 중 3,920건이 이 한도에 막혔습니다.**
게이트가 백스톱이 아니라 전략을 결정해버립니다.

실험실에서는 1억원으로 올려서 돌리고 있습니다(전략을 재기 위해). **실거래에 쓸
숫자는 별개의 결정입니다.**

참고로 이 한도는 10.6년 백테스트에서 `momentum-dca` 기준 **단 한 번도 발동한 적이
없습니다**(거부 0건). LIVE에서 처음 실행되는 코드가 된다는 뜻이기도 합니다.

### B3. 🟡 GROWTH 버킷에 종목을 추가하실지

지금 IONQ 하나뿐입니다. 슬롯 2개 중 1개만 차서 GROWTH는 **20%가 아니라 10%**로
돌아가고, 남은 10%는 CORE로 넘어갑니다(SAFE 20 / CORE 70 / GROWTH 10).
두 번째 종목이 들어오면 자동으로 20%가 됩니다.

제가 성장주를 고르지 않은 이유: 2026년에 앉아 성장주를 고르면 그 버킷의 백테스트는
전부 후견지명이 됩니다. 그리고 이 프로젝트의 기존 설계(`src/universe_review.py`)가
**모델은 제안만, 추가는 사람이**로 못 박아 뒀습니다. IONQ도 그 경로로 들어왔습니다.

**결정 필요:** 매일 리포트의 AI 유니버스 검토가 내는 후보 중에서 승인하시거나,
직접 `config.yaml`에 넣으시면 됩니다.

### B4. 🟡 변동성 조정 — 끄는 쪽이 낙폭당 수익은 더 낮습니다

`vol_adjust`를 끄면 **5개 시작연도 전부에서 수익이 +5~9%p 오릅니다.** 동시에 2014년
최대낙폭이 20.78% → **35.88%**로 뜁니다.

| | 2014 | 2016 | 2018 | 2020 | 2022 | MDD(2014) |
|---|---|---|---|---|---|---|
| 켬 (현재) | 20.98% | 21.81% | 22.57% | 33.15% | 23.39% | 20.78% |
| 끔 | 26.02% | 29.71% | 31.65% | 34.35% | 29.72% | 35.88% |

변동성 조정은 점수를 변동성으로 나눠 **많이 흔들리는 종목의 순위를 깎습니다.** 끄면
TSLA·NVDA·IONQ 같은 이름이 상위로 올라오고, 지난 10년간 그게 정답이었습니다 —
흔들린 만큼 낙폭도 컸고요.

이건 노이즈 범위를 훨씬 넘는 실제 효과입니다(비교: 리밸런스 요일을 바꾸기만 해도
2~3%p가 움직입니다. 그게 이 실험의 노이즈 눈금입니다).

**낙폭당 수익으로 보면 켠 쪽이 낫습니다.** 끄면 평균 수익이 26.18% → 33.17%로
7%p 오르지만 최악 낙폭이 21.19% → 43.13%로 22%p 오릅니다. 수익/낙폭이 1.24 → 0.77.
말씀하신 "10%p 더 벌자고 20%p 내주지 않는다"에 정확히 걸리는 거래입니다.

다만 **방어 장치와 함께 걸면 얘기가 달라질 수 있습니다** — `변동성조정 끔 +
추세이탈 매도`는 수익 28.94% / 낙폭 25.87%로 비율 1.12를 냅니다. A안(1.24)보다는
낮지만 수익이 2.8%p 높습니다. LAB 29번이 이 조합을 A 기준으로 다시 재고 있습니다.

참고로 이전 세션에서 이 항목을 "반영하지 않는다"고 결정하셨는데, 그때 측정된
효과는 +2~4%p였습니다. 측정 오류를 고치니 실제 효과가 두 배 이상입니다.

### B4-2. 🟡 손절(OCO)을 계속 꺼둘지

현재 per-position 손절이 없습니다. 하방 방어는 추세 이탈 매도뿐인데 10.6년에 3번
작동했고, 그마저 레버리지 종목만 팝니다.

기존 판단은 "8단계 백테스트가 손절 폭을 정해주지 않으므로 검증 안 된 값(-15% 등)을
넣으면 방어보다 조기 청산이 크다"였고, 그 판단은 지금도 유효해 보입니다. 다만
**LIVE로 실제 돈을 넣기 전에 인지하고 계셔야 할 사항**입니다.

## C. 알고는 있되 지금 손대지 않은 것

- **`dislocation`은 죽은 코드입니다.** 14년간 2번 발동. 켜고 끄고 배수를 3배로 해도
  결과가 소수점까지 동일합니다(LAB 10번 표). 지우지는 않았습니다.
- **`leverage_requires_trend`는 매수 경로에서 무의미합니다.** 하락장에선 레버리지
  ETF의 모멘텀 점수가 이미 음수라 후보에서 빠집니다. 이전 세션에서 확인된 내용입니다.
- **`weight_mode="flow"`는 불필요합니다.** 현금 드래그를 고치고 나니 `target`보다
  미세하게 나빴습니다. 파라미터로만 남겨뒀습니다.
- **테스트 2건이 Windows에서 실패합니다.** `tests/test_config.py`의 경로 구분자
  단정(`\` vs `/`). WSL에서는 통과하므로 기능 문제는 아닙니다.
- **`stocklens.db`는 쓰이지 않습니다.** 시세 캐시는 `bars.db`로 옮겨갔고, 이 파일은
  스키마만 남은 빈 껍데기입니다.
- **`refresh`는 캐시를 과거로 늘리지 못합니다.** `--start 2010`을 줘도 이미 최신이면
  0건 추가. 과거 구간을 넓히려면 `bars.db`를 지우고 다시 받아야 합니다.
